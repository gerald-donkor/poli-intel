# 71 — Quarterly Evidence Narrative & Evaluation Workflow

## Goal

Implement the structured quarterly evaluation workflow from spec §10.3: enable the Policy & Advocacy Officer and Programme Director to author, review, and persist a structured quarterly evidence narrative covering **policy wins**, **missed policy windows**, **evidence gaps**, and **system improvements**. 

This narrative is stored directly in Postgres, linked to the quarterly reporting cycle on `/impact`, and directly informs the next quarter's evidence ingestion priorities. It is 100% human staff-authored, traceably recorded with author and timestamp, and never invokes Gemini or AI generation.

## Decisions and assumptions

1. **Structured, staff-authored record.** The quarterly narrative is an explicitly authored staff evaluation document tied to a specific quarter key (e.g. `2026-Q2`). It is stored in a dedicated `QuarterlyEvidenceNarrative` table mapped to `quarterly_evidence_narrative`.
2. **Four distinct structured dimensions.** The evaluation captures four explicit fields per spec §10.3:
   - `wins`: Key policy wins, adoptions, and successful brief deployments.
   - `missedWindows`: Policy windows or signals where engagement was missed or delayed.
   - `evidenceGaps`: Identified research or evidence gaps that hampered policy response (used to guide evidence ingestion).
   - `systemImprovement`: One actionable suggestion for improving the EviBrief system or workflow.
3. **Role permissions.** Authoring and editing the quarterly evaluation is restricted to Policy & Advocacy Officers and Programme Directors (`canLogInfluenceEvent` / `canAuthorQuarterlyNarrative`). Research Officers and Field Officers cannot mutate narrative records.
4. **Audit and update trail.** Each record tracks `authorId`, `createdAt`, and `updatedAt`. Saving an existing quarter's narrative updates the current record and updates the author/timestamp.
5. **Zero AI generation.** The narrative must never be generated by Gemini or any LLM. It is strictly staff-authored and reflective, ensuring complete credibility and human accountability.
6. **Cohesive placement in `/impact`.** The narrative is rendered within the Quarterly Report section of `/impact` for the active selected quarter. If no narrative has been authored yet for that quarter, an empty state prompts authorized staff to record the quarter's evaluation.
7. **Bounded length & validation.** Each section is bounded (maximum 3,000 characters per field) with trimmed inputs and shared Zod validation.

## Implementation requirements

### Data layer & schema

- Define `QuarterlyEvidenceNarrative` in `prisma/schema.prisma`:
  ```prisma
  model QuarterlyEvidenceNarrative {
    id                String    @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
    quarterKey        String    @unique @map("quarter_key") @db.VarChar(16)
    authorId          String    @map("author_id") @db.Uuid
    wins              String    @db.Text
    missedWindows     String    @map("missed_windows") @db.Text
    evidenceGaps      String    @map("evidence_gaps") @db.Text
    systemImprovement String    @map("system_improvement") @db.Text
    createdAt         DateTime  @default(now()) @map("created_at") @db.Timestamptz(6)
    updatedAt         DateTime  @updatedAt @map("updated_at") @db.Timestamptz(6)

    author            StaffUser @relation("StaffUserQuarterlyNarratives", fields: [authorId], references: [id], onDelete: Restrict)

    @@index([quarterKey])
    @@map("quarterly_evidence_narrative")
  }
  ```
- Add relation on `StaffUser`: `quarterlyNarratives QuarterlyEvidenceNarrative[] @relation("StaffUserQuarterlyNarratives")`.
- Generate migration using `npm run db:migrate:new -- quarterly_evidence_narrative` and apply with `npm run db:migrate`.
- Implement `findQuarterlyNarrativeByQuarter(quarterKey: string)` and `upsertQuarterlyNarrative(data: UpsertNarrativeInput)`.

### Authorisation and Server Action

- In `lib/auth/authorize.ts`, define `canAuthorQuarterlyNarrative(role: StaffRole): boolean` allowing `programme_director` and `policy_advocacy_officer`.
- In `app/(app)/impact/schema.ts`, define `quarterlyNarrativeSchema`:
  - `quarterKey`: string (format `YYYY-Q[1-4]`)
  - `wins`: non-empty trimmed string, max 3000 chars
  - `missedWindows`: non-empty trimmed string, max 3000 chars
  - `evidenceGaps`: non-empty trimmed string, max 3000 chars
  - `systemImprovement`: non-empty trimmed string, max 3000 chars
- In `app/(app)/impact/actions.ts`, implement `saveQuarterlyNarrativeAction`:
  1. Resolve current staff user via `getCurrentStaffUser()`.
  2. Authorise caller with `canAuthorQuarterlyNarrative`. Refuse unauthorized callers immediately.
  3. Validate input with `quarterlyNarrativeSchema`.
  4. Upsert the narrative in database.
  5. Revalidate `/impact`.
  6. Return typed outcome `{ success: true, narrative: ... }` or typed error.

## Evidence classification impact

**none — no evidence data path.**
This task does not ingest, move, read, transmit, chunk, embed, summarise, or fact-check evidence subject to the section 7 classification gate. The quarterly narrative is written directly by staff about operational reflection, stored in standard Postgres columns, and never passed to Gemini.

## Hallucination-guard implications

**none.**
The quarterly evaluation narrative is written by human staff members and does not call any LLM. It does not touch brief generation, claim verification, or hallucination flag rendering.

## Security requirements

- Server Action authorises the caller before any database write.
- Client-visible schema does not leak internal authorization or role logic.
- Input fields are validated and bounded to prevent oversized payloads.
- All database queries use parameterised Prisma queries.

## Acceptance criteria

1. Policy & Advocacy Officers and Programme Directors can record and update the 4-part quarterly evidence narrative for any selected quarter.
2. Research Officers and Field Officers cannot author or modify the quarterly narrative (refused server-side).
3. The quarterly narrative is prominently displayed in the `/impact` quarterly report view for the active quarter, showing author metadata and timestamp.
4. If no narrative exists for a quarter, a clean empty state invites authorized staff to record the evaluation.
5. Editing and saving updates the record in-place with the current author and timestamp without losing existing data.
6. All automated checks (`npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`) pass cleanly.
