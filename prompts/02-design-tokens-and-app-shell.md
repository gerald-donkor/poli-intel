# 02 — Design tokens and app shell

## Goal

Replace the stock shadcn neutral theme with the EviBrief token layer, wire the three product fonts, install the full shadcn component set, and build the app shell plus route scaffolding for the five screens.

After this task, every later UI prompt can write `bg-card`, `border-line`, `text-ink-3`, `border-l-immediate`, `font-serif`, `rounded-card`, `tablet:`/`laptop:`/`desktop:`, and `animate-rise-in` and have them resolve to the handoff's values. Scope is the token layer, the fonts, the component install, the shell chrome, and honest placeholder pages. **No screen implementation.** No kanban, no editor, no evidence table, no impact map, no auth, no data layer, no Gemini, no Motion, no GSAP, no cmdk wiring. Those are later prompts and must not be started here.

## Decisions and assumptions

1. **Install the full shadcn set first, then apply the theme.** `npx shadcn@latest add --all` before touching `globals.css`, so component additions cannot clobber the token layer and the post-install sweep (Decision 3) sees every file at once. Confirms `AGENTS.md` §6 / spec §5.5's "full component set installed up front".

2. **This is Base UI, not Radix.** Custom triggers use the `render` prop, never `asChild`. Anything written from Radix muscle memory is wrong here. Nothing in this task needs a custom trigger, but the nav must not reach for `asChild`.

3. **`accent` means the green in utility space, and shadcn's accent *surface* is repointed.** This is the one genuine naming collision between the handoff and base-nova, and it needs a deliberate call rather than a merge.

   The handoff's recipes use `accent` for the **green `#1D9E75`** — `ring-accent` in the global focus state, `border-accent` on the quoted-evidence left rule, the verified citation dot. But base-nova's `@theme inline` bridge declares `--color-accent: var(--accent)`, where `--accent` is a subtle *hover surface* that its components paint with `bg-accent` / `text-accent-foreground`. Left as-is, the bridge wins and `ring-accent` silently resolves to a pale surface tint — the focus ring, the verified mark, and the quote rule all break, quietly.

   Resolution: **the handoff wins on utility naming.** Drop `--color-accent` and `--color-accent-foreground` from the inline bridge, declare `--color-accent: #1D9E75` in `@theme`, keep `--accent: var(--color-surface-tint)` in `:root` for anything still reading the raw var, and sweep the installed components that paint surfaces with `bg-accent` / `text-accent-foreground`, repointing them to `bg-surface-tint` / `text-surface-tint-ink`.

   **Guard on the sweep:** after `add --all`, run `grep -rlE '\b(bg|text|border)-accent(-foreground)?\b' components/ui/` and report the file count before editing. If it exceeds 15 files, stop and confirm — the fallback is to leave `accent` as shadcn's surface and expose the green as `--color-verified` instead, which costs a documented divergence from the handoff's recipe table. Do not silently pick the fallback.

4. **`--destructive` is unmapped, and the invalid state moves to the watch ramp.** `AGENTS.md` §11.4 and the handoff both say nothing in this product is red. But `button.tsx` proves every base-nova component wires `aria-invalid:` to `--destructive`, so simply deleting the token leaves form validation with *no* perceivable state — which fails §11.13 (WCAG AA) while satisfying §11.4.

   Both rules are satisfied by unmapping `--destructive` **and** repointing the `aria-invalid:` treatment to the watch ramp (`border-watch`, `ring-watch/20`) across the installed components. Remove `--color-destructive` from the bridge and `--destructive` from `:root`. Delete the `destructive` variant from `button.tsx` (and any sibling component exposing one) rather than leaving a variant whose token does not resolve.

5. **No dark mode.** The handoff has no dark palette and the product has one warm light theme. Delete the `.dark` block's values, but **keep `@custom-variant dark (&:is(.dark *))`**. This is deliberate and load-bearing: with the custom variant retained and no element ever receiving `.dark`, the ~50 components' inherited `dark:` classes compile to rules that never match. Removing the custom variant instead would make `dark:` fall back to Tailwind's built-in `prefers-color-scheme` behaviour, and users on a dark OS would get half-applied dark styling against a palette with no dark values — a real bug. Do not "tidy up" the dark variant.

6. **One mechanism per token name; never both.** For any name base-nova already bridges (`background`, `foreground`, `card`, `popover`, `primary`, `secondary`, `muted`, `border`, `input`, `ring`, `radius`, `chart-*`, `sidebar-*`), keep the `@theme inline` entry and set the raw value on the **un-prefixed** var in `:root` (`--card: #FDFCF9`). Do **not** also declare `--color-card` in `@theme` — `@theme inline { --color-card: var(--card) }` plus `:root { --card: var(--color-card) }` is a circular reference that resolves to nothing. EviBrief-only names (`paper`, `stone`, `line`, `sage`, `ink*`, `surface-tint*`, `primary-hover`, `primary-ink`, the four urgency families) are declared with literal hex in `@theme`.

7. **Fix the self-referential font entries.** The current bridge contains `--font-sans: var(--font-sans)` and `--font-mono: var(--font-geist-mono)`. Replace both with the handoff's declarations in `@theme` (`--font-sans: var(--font-inter), …`, `--font-serif: var(--font-source-serif), …`, `--font-mono: var(--font-plex-mono), …`). Keep `--font-heading: var(--font-sans)` — the handoff sets every heading in Inter.

8. **Nested layouts, not multiple root layouts.** One root `app/layout.tsx` owns `<html>`, the three fonts, and `globals.css`. A nested `app/(app)/layout.tsx` adds the desktop shell for `/signals`, `/briefs`, `/evidence`, `/impact`. `app/field/layout.tsx` gets its own minimal mobile chrome. Per the route-groups doc, sibling *root* layouts force a full page reload on navigation between them; nesting avoids that and keeps font loading in one place.

9. **`/` redirects to `/signals`.** The README calls the Signal Dashboard "the daily-use screen… sets the tone for the entire product". No marketing landing page is in scope. When auth lands, the redirect target becomes role-dependent (a Field Officer should land on `/field`) — leave a comment saying so, but no role logic now.

10. **The search field and avatar are honest placeholders.** The nav's ⌘K field renders at the handoff's exact dimensions but as a `disabled` `<button>`, not an `<input>` — a text input that silently swallows typing is a worse lie than a visibly disabled control. It gets its real behaviour in the command-palette prompt. The avatar is `Avatar` + `AvatarFallback` with static initials; it binds to the session in the auth prompt. Neither may fake data.

11. **Placeholder pages use the real header pattern plus `Empty`.** Each of the four screens renders its correct header block (title, subtitle, action slots) above a shadcn `Empty` state naming the prompt that will build it. This exercises the token layer on real chrome and keeps the placeholder from reading as a finished screen. Per the `shadcn` skill, use `Empty` — not a custom styled div.

12. **Add a `/design-system` specimen route.** It renders every token: the palette, the urgency ramp in its fixed order, the relevance trio, the type scale in all three families, the elevation steps, the radius steps, the governance glyphs (circle vs. square), and each keyframe. Rationale: it is the only practical way to *verify* the token layer, and it mirrors `EviBrief Design System.dc.html`. It is a developer surface, not a product feature — it carries no nav link and is reachable by URL only. **If you would rather not carry it, say so and it comes out**; the manual test steps then move onto the placeholder pages, at the cost of no single place to check a colour pairing.

13. **Add `"typecheck": "tsc --noEmit"` to `package.json`**, per `AGENTS.md` §19's instruction to add the script in the change that first needs it, and update §19's list in the same commit.

14. **No `Motion` install.** Nothing in this task needs shared-layout animation. The CSS keyframes and `--animate-*` tokens cover everything here. Motion arrives with the kanban or the audience switcher, whichever lands first, and brings `useReducedMotion()` with it.

15. **Custom breakpoints are added, defaults are left alone.** `tablet`/`laptop`/`desktop` join Tailwind's `sm`–`2xl`. Removing the defaults would be a larger change than the handoff asks for; later screen prompts use the custom three because that is where these layouts actually break.

## Evidence classification impact

**None — no evidence data path.**

The deliverable is a CSS token layer, a font configuration, ~50 vendored shadcn component files, nav chrome, and placeholder pages. There is no database client, no Prisma schema, no Gemini call, no embedding, no upload handler, no Server Action, and no Route Handler in this task. No `evidence_item` row is read, written, moved, or transmitted, so the §7 gate has no call site to sit at and no classification value is evaluated at runtime.

Two forward-looking points, since this task fixes the vocabulary the gate later renders through:

- The **classification-pending** treatment must be tokenised correctly here, because §7.5 requires the pending backlog to stay visible and the handoff makes that a *shape* distinction, not only a colour one: the governance hold is a **square** on the immediate ramp (`bg-immediate-surface`, `border-immediate-border`, `text-immediate-ink`), while a review flag is a **circle** on the watch ramp. Getting these swapped in the specimen page would propagate into the evidence and editor prompts. Colour-blind users must be able to tell them apart at all.
- The classification-pending pill and the guard-flag panel are the two surfaces §11 and the handoff forbid hiding at smaller breakpoints — they promote above the fold instead. The breakpoint tokens land in this task; the promotion behaviour is enforced in the screens that own those panels.

No placeholder page may contain invented evidence text, and no real Tropenbos content of any classification may be used as filler. Specimen and placeholder copy is synthetic and obviously so.

## Hallucination-guard implications

**None** for behaviour — nothing is generated, no claim is extracted, no flag record is created, stored, resolved, or rendered, and no approval path exists to block.

The flag's **visual contract is affected only in that its tokens are created here**, so the contract is restated to make sure they are created correctly (`AGENTS.md` §9.7, handoff motion table):

- Slate, on the **watch** ramp: surface `#E7EDF2`, border `#C6D4DF`, text `#33495A`. Never red, never `destructive`.
- Icon is a **16px circle**, 2px stroke `#496375`, filled centre dot — distinct from the classification-hold square.
- `--animate-flag-pulse` is **900ms, once**, easing background opacity 0.32 → 0 and settling to a steady 2px underline. No blink, no loop, no colour change on pulse.
- A flag is a review prompt, not an error. No error toast, no alarm.

Decision 4 is what protects this: because `--destructive` is unmapped *and* the `aria-invalid:` treatment is repointed to the watch ramp, a later implementer who reaches for shadcn's red `destructive` variant on a flag panel finds no such variant to reach for. The `grep -rn 'destructive' components/ui/` acceptance check is the enforcement.

The only looping animation in the product is the generation stepper's breath (`--animate-breathe`, 2s). If the specimen page demonstrates it, it must be the only loop shown.
